# Spec check — tickets/prod-deploy/spec.md

Reviewer read the spec as the builder. Each finding: **blocker** or **minor**.

1. **minor** — Deploy step 2 "applies the ECR repository alone first" doesn't say how (`terraform apply -target=aws_ecr_repository...` vs a separate root). `-target` prints a warning and is the obvious choice; say so, so the script isn't guessed. Also say the step needs `aws ecr get-login-password | docker login` before push.

2. **blocker** — `APP_URL` = the function URL creates a Terraform cycle. `aws_lambda_function_url` takes `function_name` from `aws_lambda_function`, so the function's `environment` can't read `aws_lambda_function_url.*.function_url`. The spec says this choice _avoids_ a cycle; it swaps CloudFront↔Lambda for Lambda↔URL. `APP_URL` is required by `app/start/env.ts` (`format: 'url', tld: false`) but only read into `appUrl` in `config/app.ts`, never used. Fix: set it to a fixed placeholder (e.g. `https://localhost`) or to the CloudFront URL and accept a two-step apply, and say which.

3. **minor** — Production deps in the image are not buildable as written. `app/` has no `package-lock.json`; the only lockfile is the root one (npm workspaces). `node ace build` copies `package-lock.json` from `app/` (assembler `packageManagerFiles`), so the usual `cd build && npm ci --omit=dev` fails. Spec should say: build context is the repo root, `npm ci -w app` with the root lockfile, then `npm ci --omit=dev -w app` (or `npm prune --omit=dev`) and copy `build/` + root `node_modules`. `.dockerignore` should then also drop `web/` and `infra/` content not needed (but keep `web/package.json`, or `npm ci` errors on a missing workspace).

4. **minor** — Lambda function URL public access: since late 2025 AWS requires the resource policy to grant **both** `lambda:InvokeFunctionUrl` and `lambda:InvokeFunction` to `*` for an auth-`NONE` URL; `aws_lambda_function_url` only adds the first. Without the second, CloudFront gets 403 `Forbidden` and the smoke check fails. Spec should name an `aws_lambda_permission` for `InvokeFunction` (principal `*`) — verify against current docs when building.

5. **minor** — Atlas M0 in AWS `eu-west-2`: confirm M0 is offered in London before the runbook commits to it; the free tier is limited to a subset of regions. Give the fallback (nearest M0 region, e.g. `eu-west-1`) so the builder doesn't stop.

6. **minor** — Lambda init is capped at 10 s; Mongo connects at boot (`providers/mongo_provider.ts`) with mongoose's default 30 s server-selection timeout. A bad `MONGO_URL` / Atlas network rule shows as a hung init and a generic 5xx through CloudFront, not a clear error. Runbook should say "check CloudWatch log group for the connect error"; optionally note `serverSelectionTimeoutMS` (an app change, which the spec says there is none of — so just document it).

7. **minor** — Contradiction: Testing says "a reviewed `terraform plan`", deploy is one command. Say whether the script runs `terraform apply` interactively (shows plan, waits for `yes`) or `-auto-approve`, and whether the ECR `-target` apply also prompts.

8. **minor** — Rollback "or pass its SHA" is undefined and inconsistent: step 3 builds the PWA from the working tree, so passing an old SHA would pair an old API with the current PWA. Either drop "or pass its SHA" or define it (checkout into a temp worktree). Also "the image is still in ECR" is only true for the last 10 deploys (keep-10 rule); since step 2 always rebuilds anyway, say rollback rebuilds rather than relying on ECR.

9. **minor** — ECR tag mutability not stated. Re-running the deploy for the same commit (e.g. after a failed apply) re-pushes the same SHA tag; with `IMMUTABLE` the push fails. Say `MUTABLE`, or "skip build/push when the tag already exists".

10. **minor** — S3 via OAC answers a missing object with **403 XML**, not 404 (no `s3:ListBucket`). A stale tab lazy-loading a hashed chunk deleted by the `--delete` sync gets 403. Acceptable, but say so, or keep old hashed assets for one deploy instead of deleting them (step 4 "files no longer in the build are deleted").

11. **minor** — Untested stories: 7 (no API caching) and 8 (new deploy reaches phone) aren't covered by the smoke check. Cheap adds: assert `/api/v1/health` response has `x-cache: Miss from cloudfront` on two consecutive calls; assert `index.html` and `sw.js` come back with `cache-control: no-cache`.

12. **minor** — Smoke check should also prove cookies pass through (story 5, "cookies … pass through" is claimed in Testing Decisions), but the listed checks only send no cookie. Sign-up can't be used (it closes sign-up — ADR-0010). Either drop the cookie claim from Testing Decisions (left to the phone acceptance) or add `GET /api/v1/me` with `Cookie: token=garbage` → 401 JSON, which at least proves the Cookie header reaches Adonis without an error.

13. **minor** — Runbook gaps a builder will hit: how to generate `APP_KEY` (`node ace generate:key --show`) and `JWT_SECRET` (`openssl rand -base64 48`); the exact `aws ssm put-parameter --type SecureString` names (`/fishtank/prod/MONGO_URL` etc.); `terraform init` with backend config for the first run; `docker login` to ECR; and for the `user:set-password` fallback, that it needs the other env vars too (`APP_KEY`, `JWT_SECRET`, `HOST`, `PORT`, `LOG_LEVEL`, `APP_URL`, `NODE_ENV`) because `start/env.ts` validates them all at boot. Also: `user:set-password` only resets an _existing_ User's password (it cannot create one). After a lost race it works only by looking up the intruder's email in Atlas and taking over that User (their Tanks come with it); deleting that User in Atlas and signing up again is the cleaner fix. The runbook should spell out which.

14. **minor** — CloudFront details unstated: `default_root_object` (the CloudFront Function covers `/`, fine, but say it), price class (`PriceClass_100` keeps cost lowest, story 19), and that the CloudFront Function must leave `/api/*` alone (it does, since it's on the default behaviour only — worth a sentence so nobody moves it to a distribution-wide spot).

Checked and fine (no finding): `HOST=0.0.0.0` passes `format: 'host'`; `JWT_SECRET` ≥ 32 check matches; force-JSON middleware makes 401/404 JSON in production; token cookie is set with explicit `secure: true`, `sameSite: lax`, 30 days (not `config/app.ts` defaults), so it works over the CloudFront HTTPS origin; production CORS `origin: []` doesn't block same-origin POSTs (non-preflight requests pass through, only headers are omitted); `AllViewerExceptHostHeader` + `CachingDisabled` is the right pair for a function URL origin; avoiding custom error responses is correct; health route returns `database: 'connected'` as the smoke check expects; PWA's `navigateFallbackDenylist` keeps `/api` off the service-worker fallback.
