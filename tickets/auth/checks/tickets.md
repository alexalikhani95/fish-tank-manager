# Ticket check: auth

- **minor** · 01 · The spec's hand check (boot refuses a missing `JWT_SECRET` and a 31-char one, "recorded in the PR") is in no ticket, so no implementer will do it or report it. · Add to 01: "Boot by hand with no `JWT_SECRET` and with a 31-char one; both refuse to start. Put the result in the report." (The PR reminder to add `JWT_SECRET` to `app/.env` can stay with the orchestrator, but say so in `log.md` or 01.)
- **blocker** · 01, 05 · The JSON body parser trims every string value by default (`trimWhitespaces: true` in `@adonisjs/bodyparser` `defineConfig`, checked in `app/node_modules/@adonisjs/bodyparser/build/define_config-*.js` and its JSON reviver). So the API silently trims passwords, but `user:set-password` reads the prompt untrimmed. A passphrase with a leading or trailing space set by the command can never log in over the API, which locks the keeper out (against story 28 and "length as the only rule"). Register also turns a 12-char password ending in a space into an 11-char one and gives a 400. · In 01, set `json: { trimWhitespaces: false }` in `config/bodyparser.ts`. Email is already trimmed by Zod, and Tank `name` by Zod `.trim()` and Mongoose, so nothing else relies on it. Add one Seam 1 test: register with a password that has a trailing space, then log in with the exact same string (in 02) and get 200. Add a line to the spec so 05 knows passwords are never trimmed.
- **minor** · 01 · "Only the JSON body parser remains": deleting the `form` and `multipart` keys from `config/bodyparser.ts` does not turn them off, because `defineConfig` merges in defaults (`types: ['application/x-www-form-urlencoded']`, `['multipart/form-data']`). The form-encoded test would catch this, but the implementer will lose a loop on it. · Say so in 01: set `form: { types: [] }` and `multipart: { types: [] }` (`#isType` returns false for an empty list).
